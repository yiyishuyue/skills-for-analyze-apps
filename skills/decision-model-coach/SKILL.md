# Decision Model Coach

帮助用户回答“现在该采取什么行动、承担多少风险、什么证据会改变建议”。用户用自然语言描述业务；由你整理口径、选择方法和核对计算，不让用户填写专业参数表。

## 入口：先定位问题

从已有上下文提取答案，只补问缺失且会影响行动的信息；每轮优先1～3个相关问题：

1. **现在具体要选什么？** 例如直接开发、有限验证或暂缓；同时确认不行动的代价。
2. **当前有什么真实证据？** 区分个人判断、用户口头意向、实际使用、复购/付费与可比较实验。
3. **这次最想得到什么，最多能承担什么？** 目标、期限、现金/工时上限和不可接受的损失。反馈时间、上线时间和回本时间分别记录。

先用一句话复述决策，再说明证据允许回答到哪一步。允许用户回答不知道；优先寻找已有数据，关键未知不能可靠补足时给获取证据的办法。

## 选择最少且足够的方法

| 情况 | 主要工作 | 暂不支持的断言 |
|---|---|---|
| 有想法，缺少外部需求证据 | 需求验证、行为漏斗、有限投入计划 | 需求成立、未来利润、成功概率 |
| 成本收益可比，周期明确 | 增量现金流、单位经济、盈亏平衡 | 用行业均值预测自己的表现 |
| 有明确互斥情景及可信概率 | 期望比较；多阶段则逆向归纳 | 把“可能”自动换成概率 |
| 输入变化可能改变选择 | 有依据的情景或敏感性、反转边界 | 把扫描点占比当发生概率 |
| 多个目标冲突 | 用户偏好、权重与排名稳定性 | 普遍正确的权重 |
| 先获取信息可能改变后续行动 | 验证设计；输入充分才算信息价值 | 验证天然划算、测试等于完美预知 |

不默认先做MVP：已有原型、证据充分、行动容易撤销，或等待/测试代价更大时，应比较直接执行与有限验证。没有证据时也不能无限追问或无限验证。

## 行动建议的证据闸门

- 建立简短参数记录：值、单位、周期、人群/样本、来源、推导或假设、确认状态。行业参考不能冒充自有观测；目标和实验阈值不是预测。
- 先筛掉违反已知硬约束的方案，再比较可行方案。期望值高仍可能超过现金或损失承受能力；必要时同时列最坏情景与可逆性。阈值是目标线，不是完整的约束求解器。
- 比较同一评价周期、币种与流量分母；收入、利润、现金到账和客户LTV分别表达。区分新增成本、沉没成本和机会成本，避免重复计费。
- 重要定量建议先独立核对关键公式的量纲，例如“月数×每月损失”已经是金额，不再乘12。至少选择一个可手工核对的基准或边界点复算；来源有公布结果时记录差异及舍入口径，不调整输入凑答案。输入检查不能识别所有业务公式错误。
- 概率须有来源或明确接受的假设；相关事件用条件概率或互斥联合情景，不能默认独立。上下限不自动代表均匀分布，情景不是概率预测。
- 概率敏感性必须保持同一节点的分支完整：改变失败概率q时，同时更新互补概率1−q；有条件依赖时更新相应条件关系。当前后端不原生扫描概率，另用透明计算并独立核对，不冒充已支持的变量扫描。
- 区分数值并列、估计不确定和统计等效。差异可能被测量误差覆盖时，报告候选及缺口；不能只按小数排名。权重来自用户偏好，检查合理权重变化是否改变建议。
- 主动寻找能推翻建议的解释，例如样本变化、费用遗漏、幸存者偏差、相关性或时间窗口差异。敏感性范围须有依据，有限网格未发现反转不代表全域稳健。
- 可以给有条件的定性建议、符号关系或明确标注的估算；关键未知禁止包装成确定结论。无法量化的风险保留文字说明。

## 把建议转为下一步

当验证有必要，阅读 [验证实验](references/validation-experiments.md)：明确待验证假设、可接触对象、最小体验、行为指标及分母、投入与时间上限、继续/调整/暂停条件。

建议的预算、样本量和阈值注明“建议值及理由”，不要冒充用户承诺或统计保证。没有招募渠道，先验证接触用户的可行性。缺样本、测试失败或指标不显著，分别说明其含义。

需要经济公式、概率树、条件投资、EVSI/EVPI时，阅读 [定量方法](references/analysis-methods.md)。使用前核对适用条件；多阶段决策不能把尚未触发的投资提前扣到全部路径；信息价值要按真实测试准确性更新后验，成本只计一次。

## 可选计算后端

只有输入足够、问题属于支持范围且运行环境允许时，阅读 [计算指南](references/verified-engine.md)，使用 `scripts/run_verified.py`。它只需Python标准库，不依赖WorkBuddy账号或服务。纯聊天环境仍可使用流程，但不能声称运行了程序。

支持平面方案、每方案单层互斥情景、独立分布期望及显式范围扫描；不支持递归树、EVSI自动求解、需求曲线估计、权重学习或通用约束优化。超出范围时另用透明可核对的方法，不伪装成已经支持。

默认不扫描固定参数。敏感性需显式范围与依据，业务有效域用domain约束。确定性结果称“基准情景值”；概率模型称“假设条件下的期望值”。并列列候选，不强选第一项。通过输入检查仅说明格式与指定计算约束成立，不证明来源真实或模型科学。

保存输入、来源和结果；程序产出的数字引用decision-result.json，原始事实与补充推导可另引已注明来源。报告必须解释输入口径与计算，而不是只展示SVG。

## 输出一份能执行、能反驳的建议

按实际问题展开，通常包括：

- **当前建议及成立条件**：证据允许时明确推荐，否则说明暂不能选择的原因与最小补证据动作。
- **主要取舍**：目标、阶段、可行方案、成本/损失上限、为什么选用当前方法。
- **证据与未知**：事实、推导、外部参考、假设分开；展示关键计算与误差限制。
- **下一步与复盘**：动作、资源边界、时间或触发事件；什么新证据会让推荐变成哪个替代行动。

不强制利润、概率树或二维图。输入变化、来源更新或产品/人群变化后，旧建议要重新检查。

## 检验本技能

分别报告指令/场景检查、程序回归、真实案例回放、前瞻业务效果；这四种证据不可混称。合成算例不是真实实验，已知答案的案例回放不是盲测，单个案例符合结果不证明长期建议质量提升。

当前验证范围及未完成项见 [验证记录](references/validation-status.md)。需要行为复核时使用 [场景验收](references/behavior-cases.md)，这些是人工复核材料，不冒充独立Agent盲测。版本改进要针对已发现的问题；保留失败记录与可重跑输入。

完整的单层概率树与敏感性案例见 [管道风险验证](examples/pipeline-risk/case-report.md)。其数据为真实项目的公开评估输入；先检查来源口径，不把论文估计和压力测试当成实测事实。

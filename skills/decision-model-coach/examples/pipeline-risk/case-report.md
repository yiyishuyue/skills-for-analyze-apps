# 这次真正检验了决策树和敏感性分析

**结论：在论文公开假设下，五个方案中详细勘测的预期增量成本最低；参数变化时，推荐确实能够反转。**

这是Dey（2001）真实石油管道项目的公开模型回放。数据位置为表VI（期刊第646页），单层树结构见图5。原文：[作者公开全文](https://www.researchgate.net/publication/40499031_Decision_support_system_for_risk_management_a_case_study)，DOI：10.1108/00251740110399558。

## 业务问题与输入口径

比较五种施工风险应对，目标是最小化“应对费用＋预期延期机会损失＋预期直接超支”。金额统一用百万美元，延期用月。方案与所列失败后果取自论文；失败概率及严重程度属于项目专家评估，不是观测频率。每月延期机会损失7.5是论文估计。

## 概率树怎么算

选择每一方案后，分“失败”与“未失败”两条互斥分支；应对费用两条分支都承担，失败分支再加延期与超支。延误和超支在同一失败分支共同出现。

以详细勘测为例：

- 失败分支：概率0.158，成本12＋2×7.5＋4＝31。
- 未失败分支：概率0.842，成本12。
- 回溯：0.158×31＋0.842×12＝15.002。

五个方案都按同一口径计算，根决策节点选预期成本最小者。完整图见 [单层决策树](decision-tree.svg)。

| 方案 | 独立重算的预期成本（百万美元） |
|---|---:|
| 开展详细勘测 | 15.002 |
| 采用更优技术 | 20.696 |
| 聘请专家项目团队 | 28.023 |
| 不增加应对措施 | 35.504 |
| 采取全部应对措施 | 56.850 |

论文把勘测结果列为约15；其余公布值也有不同程度舍入。本次保留原始概率与损失重算，没有调参数去凑整数。上述费用不含所有方案共同的项目本金，也不是实际已发生的最终成本。

## 敏感性一：什么损失水平会改变推荐

设每月延期机会损失为r（百万美元/月）：

- 勘测：12＋0.158×(2r＋4)。
- 技术：3＋0.158×(12r＋22)。

两式相等，得到r＝3.8962025316。程序扫描与独立代数解一致。在新增压力测试区间0～7.5中：

| r（百万美元/月） | 全部五方案比较后的推荐 |
|---|---|
| 0、3 | 采用更优技术 |
| 约3.8962 | 勘测与技术打平 |
| 5、7.5 | 开展详细勘测 |

0～7.5是从零损失边界到原文基准的压力测试范围，不是论文的置信区间或概率预测；没有把扫描格数当成发生概率。原生后端的 [扫描结果](result/decision-result.json) 保留了反转位置。

## 敏感性二：勘测的失败概率估错会怎样

固定其余公开输入，令勘测失败概率为q，则勘测预期成本＝12＋19q。与技术的20.696相等，得到q＝0.4576842105。

在本次0～1的结构压力测试中，低于该边界选勘测，高于该边界选技术，边界上列出两个候选。程序逐个核对101个概率点，并同步更新1−q，所有节点的概率始终合计为1。

这一部分由案例附带计算逐次调用后端完成，后端目前没有原生“概率扫描”接口。阈值是输入模型的推导，不是对项目真实失败概率的重新估计。

## 还能检出什么错误

- 负概率、概率不合计为1、待确认来源、超出声明业务域的输入会被阻止。
- 应对费用在每个终端分支只计算一次；没有将失败时延期与超支拆成独立随机事件。
- 明确增加一个假设性“前期应对支出最多10”约束后，先筛除不可行方案，最优可行方案变成技术。10是验收用条件，不是原项目预算；筛选发生在主分析流程，后端不自动求解预算约束。
- 故意把已经按月计算的延期损失再乘12，通用输入检查仍会接受。独立公式核算发现错误。因此V1.4.1增加量纲检查与基准/边界复算要求，没有将这一错误误报为通用闸门能自动识别。

## 通过范围与未证明的部分

本次21项案例检查通过；既有33项程序回归和6项兼容检查另行运行。这些是不同层次的检查，不是60个真实业务案例。

通过的是：单层概率决策树、成本回溯、全部方案排序、变量和概率敏感性、反转边界、并列处理及指定错误检测。输入、结构化输出和逐项验收见 [输入](decision-spec.json)、[结果](result/decision-result.json)、[21项记录](result/verification.json)。

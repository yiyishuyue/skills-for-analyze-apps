# 定量方法：仅在输入足够时阅读

这些公式不是必填模块；实际问题的目标、约束和证据优先。多阶段、EVSI和多目标模型需要另行透明计算，当前Python后端不自动支持。

# 五、第三阶段：参数推导和数据来源

Agent 必须主动帮助用户获得参数。

## 5.1 行业数据

当需要行业参考值时：

1. 识别行业、地域、商业模式和目标人群。
2. 优先检索官方统计、上市公司披露、可靠行业研究和真实业务案例。
3. 记录数据年份、地域、样本、统计口径。
4. 判断行业数据是否适用于用户业务。
5. 向用户说明适用性限制。
6. 必要时提供多个参考区间，而不是一个未经验证的精确数字。

行业平均值不能直接当成用户自己的真实表现。

## 5.2 自有产品数据

根据业务类型主动建议数据来源。

| 业务类型 | 重点数据 |
|---|---|
| AI 产品 | 激活率、留存率、付费转化率、推理成本 |
| SaaS | ARPU、CAC、LTV、Churn、毛利率 |
| 电商 | 客单价、转化率、退货率、复购率 |
| 广告投放 | CPM、CTR、CVR、CPA、ROAS |
| 内容平台 | 曝光、点击率、互动率、粉丝转化 |
| 线下业务 | 客流、客单价、坪效、人力成本 |

如果没有数据，提示用户从后台、业务报表、竞品资料或历史记录中获取。

## 5.3 参数推导

根据实际业务选择公式。

广告投放漏斗：

曝光量 = 广告预算 / CPM × 1000

点击量 = 曝光量 × CTR

转化用户 = 点击量 × CVR

收入 = 转化用户 × ARPU

利润 = 收入 - 投放成本 - 其他增量成本

基础商业模型：

毛利 = 收入 - 可变成本

净利润 = 收入 - 固定成本 - 可变成本

盈亏平衡销量 = 固定成本 / 单位贡献利润

LTV 简化模型：

LTV = ARPU × 毛利率 / 流失率

使用公式时，必须检查口径、统计周期和适用条件。

## 5.4 参数记录

每个参数都应保留：

- 参数名称
- 数值及单位
- 数据来源
- 统计周期
- 计算口径
- 是否用户确认
- 可信程度
- 取值范围
- 假设说明

必须区分实际数据、推导数据、外部参考数据和假设数据。另行标记用户目标、待确认的试验上限、判断阈值和纯演示参数。

免费验证阶段先评估新增现金支出、工时、有效行为证据和验证成本。没有收入时现金净流量可为负，但这本身不能证明产品无价值。工时先单列；只有存在合理且说明过的机会成本口径时才折算货币。已有开发成本作为沉没成本记录，不重复计入今天起的增量决策。

# 六、第四阶段：决策树分析

## 6.1 适用条件

当存在多个备选方案，并且不同方案可能产生不同结果，且结果具有可估计的发生概率时，使用决策树。

## 6.2 节点定义

D：Decision Node，决策节点。

代表用户可以主动选择的行动。

C：Chance Node，机会节点。

代表外部不确定事件。

T：Terminal Node，终端节点。

代表最终结果以及对应收益或成本。

## 6.3 建模要求

从初始决策开始：

1. 建立所有备选方案。
2. 识别各方案可能出现的结果。
3. 为结果分配概率。
4. 计算各终端节点净利润。
5. 从终端向前逆向计算。
6. 在决策节点比较可选路径。
7. 找出当前条件下的最优路径。

同一机会节点的概率之和必须为 100%。

## 6.4 期望值计算

单个机会节点：

EV = Σ(Pi × Vi)

其中：

Pi 为事件发生概率。

Vi 为该事件对应的净利润或价值。

对于收益最大化：

V(D) = max(V1, V2, ... Vn)

对于成本最小化：

V(D) = min(V1, V2, ... Vn)

多层决策树必须使用逆向归纳法。

## 6.5 分阶段投资

特别注意识别：

- 一次性投资。
- 分阶段投资。
- 有条件的追加投资。
- 根据前期结果决定是否继续。
- 获得新信息后重新选择。

后续投资必须放在相应的条件分支上。

不得将未触发的投资提前计入所有路径。

同时计算累计收益、累计成本和最终净利润。

## 6.6 计算注意事项

- 区分沉没成本和增量成本。
- 避免重复计算成本。
- 统一统计周期。
- 长期现金流应考虑折现。
- 处理概率之间的依赖关系。
- 不得将相关事件默认为独立事件。
- 期望值最高不代表所有用户都应该选择该方案。

必要时补充最坏情景、最好情景和风险承受能力分析。

# 七、第五阶段：敏感性分析

## 7.1 分析目标

当重要方案已有可用目标函数或计算关系，且变量变化可能影响行动选择时分析；无需先建立概率决策树：

1. 哪些变量最影响利润？
2. 哪些变量变化可能让方案亏损？
3. 需要达到什么指标才能打正？
4. 哪些变量组合能够实现盈利？
5. 当前结论是否稳健？

## 7.2 选定关键变量

优先选择：

- 对结果影响最大的变量。
- 用户最不确定的变量。
- 最容易被验证的变量。
- 可能改变方案优劣的变量。

从最可能改变推荐的变量开始；单变量足够时不强制二维。只有两个变量均有合理范围且联动有分析价值时才生成二维矩阵。

## 7.3 确定参数范围

参数范围优先来源于：

1. 用户历史实际数据。
2. 业务预测。
3. 行业参考。
4. 悲观、基准、乐观情景。
5. 业务实际可实现的上下限。

不允许仅为了生成整齐的表格而随意设置参数。缺少范围时优先给符号公式或补数方法。如为解释模型另作压力测试，明确标记演示用途和非预测性质，不能用其支持实际推荐或声称完成真实业务验证。

## 7.4 单变量敏感性分析

固定其他参数，改变一个变量，观察结果变化。

例如：

利润 = 获客量 × ARPU - 投放成本

固定投放成本和 ARPU，只改变获客量。

记录每种情况下的利润和方案排名。

## 7.5 二维敏感性分析

固定其他参数：

Result = f(X, Y | Other Parameters Fixed)

例如：

X = 获客量

Y = ARPU

利润 = X × Y - 投放成本

生成矩阵：

| 获客量 / ARPU | ARPU A | ARPU B | ARPU C |
|---|---:|---:|---:|
| 用户量 A | 利润 | 利润 | 利润 |
| 用户量 B | 利润 | 利润 | 利润 |
| 用户量 C | 利润 | 利润 | 利润 |

每个单元格都必须由同一个模型公式计算。

## 7.6 盈亏平衡分析

当：

利润 = 0

即可求出盈亏平衡边界。

例如：

获客量 × ARPU - 投放成本 = 0

则：

ARPU = 投放成本 / 获客量

或者：

获客量 = 投放成本 / ARPU

必须明确解释：

- 当前基准值。
- 盈亏平衡值。
- 盈利区间。
- 亏损区间。
- 距离临界值的差距。

仅在多个变量的范围和组合均有依据时生成二维打正区间。非货币目标应求目标达成或推荐反转边界，不强行称为盈亏平衡。

## 7.7 多变量分析

必要时增加：

- Tornado Chart：龙卷风图。
- Heatmap：敏感性热力图。
- Break-even Curve：盈亏平衡曲线。
- Scenario Matrix：情景矩阵。

当变量之间存在相关性时，不能随意组合不可能同时发生的取值。

## 7.8 概率分析的区别

敏感性分析默认是确定性参数变化。

如果需要计算盈利概率，必须额外获得变量的概率分布。

不能因为某个区间能够盈利，就直接声称该区间具有某种发生概率。

# 八、验证实验与信息价值

## 8.1 把验证建议转为可执行方案

当现有证据不足以支持更大投入且低成本验证可能改变行动时，阅读 [验证实验](validation-experiments.md)。

交付最小试验：待验证假设、目标对象与招募途径、最小体验、观察指标及分母、现金和时间上限、判断时间、继续/调整/暂停条件。明确哪些值来自用户，哪些是待确认建议。

不默认所有项目都需要 AB 实验或 MVP。若已有充分证据、行动可快速撤销，或测试比直接执行更昂贵，应比较直接执行与验证的取舍。尚无招募渠道时先验证可接触性，不承诺一个月即可获得特定人数的反馈。

## 8.2 输入充分时才计算信息价值

定义状态 θ、行动 a、可比较价值 V(a,θ) 和测试结果 y。要求有来源或明确认可的先验 P(θ)、测试似然 P(y|θ)、测试后可行动的规则、各行动价值与信息成本。

- 无信息最优值：V0 = max_a Σθ P(θ)V(a,θ)
- 有样本信息值：VS = Σy P(y) max_a Σθ P(θ|y)V(a,θ)
- EVSI = VS − V0；净信息价值 = EVSI − 测试成本
- EVPI = Σθ P(θ) max_a V(a,θ) − V0

用贝叶斯更新计算后验；在相同可选行动、价值和成本口径下检查 0 ≤ EVSI ≤ EVPI。测试后选择发生在观测结果之后，不能把完美预知状态当成普通试验。

测试误判、延误和无法执行后续选择会影响价值。现金流中已计入的测试成本不再扣一次。数据不足时说明不能可靠计算 EVSI，改为定性描述：什么结果改变什么行动、为何该证据值得获取。

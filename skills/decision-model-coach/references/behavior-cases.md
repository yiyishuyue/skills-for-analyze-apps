# 行为验收材料

用途：更换模型或软件后，用真实对话检查Skill是否按意图工作。以下是设计检查与预期行为，不是独立Agent盲测的成绩。不要把“文档写了”当成“运行时一定遵守”。

| 输入场景 | 必须观察到的行为 | 失败标志 |
|---|---|---|
| 自己使用的AI决策罗盘，免费验证，一个月内反馈，没有用户证据 | 区分需求验证与回本；确认接触用户的办法、投入上限和能改变行动的行为证据 | 编造收入、成功率或保证样本量 |
| 已有可逆的小改动，实施比测试便宜，已有用户证据 | 比较直接执行与实验的净代价 | 无论情况都推荐先做MVP |
| A期望收益高，但最坏损失超过明确预算；B收益低且能承受 | 将A标为约束不满足，提出分阶段/缩小投入或B | 直接推荐最高期望值 |
| 两个随机变量同时高低，具有依赖关系 | 用完整联合情景或条件关系 | 默认独立相乘 |
| 没有用户认可的多目标权重 | 解释偏好冲突、补问优先级，或给条件选择 | 发明科学通用配比 |
| 只给参数上下限、没有概率 | 情景或边界比较；说明不能估盈利概率 | 自动均匀分布、将盈利格数除以总格数 |
| 两个方案仅有很小的估计差异 | 讨论数据误差和行动代价、保留候选 | 把小数排名当成统计显著 |
| 下方ZipRecruiter回放 | 仅比较已指定的价格和同口径首购收入 | 宣称找到了全局最优价、验证了续费或Skill通用效果 |

建议记录：原始请求与数据、模型/软件、Skill版本、实际回答、失败及修改。后续前瞻验证应提前锁定评价标准、保留无Skill/旧版对照，并检查建议可执行性、错误率和实际结果；同一案例反复改到答对，只算开发回归。

# 早期产品验证实验

仅在缺少关键业务证据、且获取证据可能改变行动时使用本参考。

## 1. 写出可被推翻的假设

把“用户喜欢”拆为可观察主张，例如目标用户能独立完成关键流程、能获得可描述的价值、在新需求出现时主动复用。不要一次测试过多机制。

说明若假设不成立，会停止、调整哪项投入。已有原型能测试该假设时优先复用，不把完整上线当作获取第一条反馈的前提。

## 2. 定义对象与触达方式

记录目标对象、使用场景、招募来源、可接触人数，以及是否为熟人或激励用户。没有招募渠道时先验证可触达性。

用户选择开放探索时，允许接收不同问题，但标记场景后分组比较；不要把不同任务、频次和后果的样本混成一个效果指标。

## 3. 保留最小体验闭环

围绕假设保留输入、核心服务、可理解的结果和后续行为观察。测试方式可以是现有原型、人工辅助或小规模上线，具体选择受可用工具和发布条件约束。明确人工介入，让“创始人陪跑有效”与“产品独立有效”可区分。

## 4. 明确行为指标和分母

可按业务选择：
- 完成率 = 完成核心流程人数 / 实际开始人数。
- 行动率 = 在约定观察窗内报告或证实采取行动人数 / 完成核心流程且已到回访时间的人数。
- 回访响应率 = 有效回应人数 / 已到回访时间且已联系人数；失访单列为未知，不自动当作未行动。
- 复用：约定观察窗内自发发生第二次有效使用；记录观察人数、触达方式和再次出现需求的机会。
- 验证成本 = 新增试验现金支出 / 有效行为证据人数；分母为零时标记无有效证据，不能除零。
- 工时、人工帮助次数、完成耗时，与现金支出分列。

只有同时满足分母定义才计算指标；不同观察窗不直接混算。主观满意、行动、付费和结果改善分别记录。行动或自报改善不证明因果，也不等于建议正确。

## 5. 设置投入上限和判断条件

现金、工时、人数和截止时间可以由 Agent 提议，但逐项说明来源及状态：用户约束、估算或“建议值，待用户确认”。阈值服务于当前下一步决策，不冒充行业标准或统计显著性。

试验前明确：
- 继续：哪些证据支持哪一小步追加投入。
- 调整：哪些现象指向流程、场景或价值主张问题。
- 暂停：何时达到投入上限，或关键条件不再成立。
- 证据不足：招募失败、失访或样本不适配时，不能直接断言没有需求。

## 6. 记录与归因

建议记录匿名编号、任务类型、开始和完成情况、输出后的行动、回访响应、复用、人工介入、现金与工时。仅收集本轮判断所需的信息。

熟人反馈、激励、创始人陪跑、自然决策趋势和失访会影响结论。确需评估相对效果且资源允许时设置可比较对照；随机化、样本规模、观察窗和停止规则需与目标匹配，不能凭几个好评宣称显著提升。

## 7. 形成下一轮决策

交付当前证据、适用范围、反例和缺口；把每种观察结果映射为可执行行动。区分“实验已设计”“已招募”“已运行”“已有结果”和“足以支持当前决策”，不要把设计完成称为市场验证通过。

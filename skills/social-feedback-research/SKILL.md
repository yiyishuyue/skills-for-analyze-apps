# 社媒用户观点调研

从 x-feedback-insights 独立复制升级，保留原版；本目录自包含，无需安装原版。继承原话证据、迁移路径、竞品借鉴和行动建议，扩展到跨平台、正负及中性观点与不同取数条件。

## 1. 三问入口

从上下文补齐，已知不重复问：
1. 想了解谁对什么问题的看法，结果用于哪个决定？
2. 重点平台、时间范围、语言是什么？不确定时根据目标人群提出候选平台，说明选择理由。
3. 已有材料，还是需要代为寻找？是否有可用的连接服务、浏览器访问或采集预算？

先说明本轮范围、能交付什么及主要缺口。不默认英文或 X，不要求每次都做竞品对比。

## 2. 验证取数能力

开始采集前读取 [取数与人工采样指南](references/collection-playbook.md)。发现实际可用的搜索、平台连接或浏览器工具，不照搬 Grok Bot 的工具名、参数和限额。Skill 文件本身不提供平台访问能力。

按平台小量试采，检查搜索结果、正文、评论/回复、时间、链接分别是否可读；记录实际读到的层级和失败原因。搜索摘要不算完整原文，正文可读不代表评论可读。二手总结不能冒充直接抓取。

| 条件 | 路径与交付范围 |
|---|---|
| 可用平台接口/连接服务 | 核对字段、时间范围、费用和配额，试采后检索；仅报告取得的内容 |
| 浏览器能访问 | 读取公开或已授权访问的页面；需登录时由用户在平台完成，注明排序/折叠限制 |
| 仅通用网页搜索 | 找线索并打开原文核验；无法核验的摘要单列为线索 |
| 自动取数失败或已有附件 | 给人工采样步骤，分析截图、文本或导出数据；结论限于已提供样本 |

同类失败经一次诊断性替代尝试仍是相同障碍时切换路径，不持续撞登录、验证码或风控。未经确认不启用收费采集。无原始材料时交付采样计划，不生成虚构观点报告。

## 3. 平衡检索与采样

围绕研究问题组合产品别名、场景和多种立场：
- 中性：产品名 + 使用体验/怎么用/评价/场景。
- 正向：好用/推荐/继续使用/解决了什么。
- 负向：问题/失望/广告/退款/不再使用。
- 行为：切换/卸载/购买/续费/替代，并核对 from→to。

仅在用户指定投诉调研时聚焦负面，并说明选样条件。记录查询、筛选条件、排序、采集时间和排除原因；去重转发、相同截图和复制文案。疑似营销或机器人单独标注，无法确定的账号不判定为真人。

检索失败、覆盖不足与讨论少分别说明。没有搜到不能证明没有需求；变更平台或研究主体须说明依据，实质改变对象前与用户对齐。

## 4. 编码、核验与提炼

每条材料记录：证据 ID、平台、原话、观点标签、使用场景、立场、帖子/回复层级、发布日期（未知留空）、来源链接或附件位置、上下文、核验状态。可区分的账号与讨论串用去标识化编号去重，避免传播无关个人信息。

原话保持原文，翻译与解读另列。仅引用支撑结论所需的短句，并遵守当前环境的引用限制。截图看不清或 OCR 存疑处标待核对，不补写。行为自述与已独立核实的行为分开。

分别判断：
- **可追溯程度**：直接读取原文 / 可定位附件 / 搜索片段或转述，以及上下文完整性。
- **支持力度**：具体场景或行为自述、独立案例重复、笼统评价。多语言或高点赞本身不提升可信度，同一传播链不算多个独立案例。

按场景和问题聚类，同时列支持、反对、例外与未知。报告本次样本条数/可区分账号数，不推断全体用户比例。跨平台分别列样本与覆盖，识别搬运，不比较未对齐的声量。

有产品比较需求时输出 `产品 | 用户怎么说 | 证据 ID | 对目标产品意味着什么`；有迁移证据才列迁移路径。明确区分事实、用户自述、分析推断和待验证假设。

## 5. 从证据到行动

输出 `问题/机会 | 证据 ID | 影响及不确定性 | 建议动作 | 如何验证`。需要时用 P0–P3 表示建议优先级，结合目标、影响和约束，不仅凭帖子数就断言不改一定流失。保留支持现有做法的证据。

社媒观点用于发现线索，不能直接证明市场规模、支付意愿或因果。需要投入选择时可把证据包交给 decision-model-coach；涉及定价时先补使用/交易或实验数据，再交给 pricing-revenue-coach。均为可选协作，不是安装依赖。

## 6. 交付与检查

按 [报告模板](templates/report-outline.md) 裁剪，写入用户指定位置或当前可写工作目录，提供文件链接；短任务可聊天交付。开头写结论和证据局限，不强凑章节。

交付前确认：关键结论可追溯；原话与解读分开；正文/评论覆盖说清楚；正负和例外未被选择性忽略；数量只指实际样本；没有宣称完成未发生的抓取、接口验证或平台支持。
